# Технический дизайн: системы, данные, зависимости, оптимизация

## 1. Список систем

| Система | Ответственность | Сохраняется |
|---|---|---|
| **TimeService** | день, фаза (`preparation` / `open` / `closing` / `report`), игровые минуты, 1 с = 1 мин | да |
| **EconomyService** | баланс, транзакции по категориям, проверка «хватает ли денег» | да |
| **DailyLedger** | учёт дня, прибыль, движение денег, история дней | да |
| **ProgressionService** | XP, уровень (не снижается), лицензии, награда за обучение | да |
| **ReputationService** | 0–100, итог визита по главной проблеме | да |
| **InventoryService** | секции (SKU, count, reserved), коробки (SKU, count, open, место), цены | да |
| **EquipmentService** | купленная мебель, позиции/повороты, валидация расстановки | да |
| **OrderService** | заказ у поставщика: требования, деньги, места в зоне доставки, создание коробок | — |
| **SupplierService** | знакомства, дистанционный заказ (ур. 4 + 5/5) | да |
| **CustomerDirector** | расписание визитов на смену, лимит одновременных, точки появления | да |
| **CustomerAgent** | FSM покупателя, список, корзина, резервы, очередь, оплата | да (активные) |
| **CheckoutService** | очередь (4), сессия кассы (сканирование, итог, карта/наличные, сдача), оператор | да |
| **StaffService** | кассир: найм, зарплата за смену, автокасса | да |
| **DirtService** | грязь (тип, позиция, вес), чистота, появление от покупателей | да |
| **RestorationService** | 6 досок, 4 паутины, 4 мусора, 4 пятна; разрешение на открытие | да |
| **StoryService / Tutorial** | интро, звонок, шаги обучения, финал (3 дня подряд) | да |

| **DayNightSystem** | небо, солнце, туман, фонари, окна, экспозиция по времени | — |
| **AssetManager** | загрузка/кэш GLB, прогресс, фолбэки, общие материалы | — |
| **SaveManager** | IndexedDB слоты, автосейв 600 с, версии схемы | — |
| **Audio** | синтез звуков WebAudio, громкости по каналам | — |
| **UI** | HUD, планшет, модалки, меню, настройки | — |

## 2. Зависимости

```text
TimeService ─────────────┬──► CustomerDirector ──► CustomerAgent ──► CheckoutService ──► EconomyService
                         │                             │   ▲              │                  │
EquipmentService ─► InventoryService ◄──────────────────┘   │              ▼                  ▼
        ▲                  ▲     ▲                          │        ProgressionService   DailyLedger
        │                  │     └── OrderService ◄── SupplierService      │
  ProgressionService ──────┘          (деньги, лицензии,     (знакомства)   ▼
   (уровень/лицензии)                  холод/мороз, места)            ReputationService ◄── DirtService
                                                                                ▲
RestorationService ──► (разрешение открыть смену) ──► TimeService               │
StoryService ◄── события всех систем (шаги обучения)                    CustomerAgent (итог визита)
SaveManager ──► snapshot()/restore() всех сервисов
```

Порядок инициализации: данные → сервисы → мир (виды) → игрок → UI → загрузка сейва (если есть) → цикл.

## 3. Ключевые модели данных

```ts
interface ProductDef { id; name; supplierId; storage: 'ambient'|'chilled'|'frozen';
  wholesalePrice; defaultSellPrice; licenseId: LicenseId|null; modelId; boxSize: 8 }

interface StockSection { id; furnitureId; index; storage; sku: string|null;
  count: number;      // логический сток (принадлежит магазину и лежит на полке)
  reserved: number;   // зарезервировано покупателями, идущими к полке (count − reserved = доступно)
  // видимые единицы = count − pendingRemovals (анимация «взял») — рисует ProductView
}

interface BoxState { id; sku: string|null; count; open: boolean;
  location: { kind:'delivery', slot } | { kind:'rack', rackId, slot } | { kind:'floor', x, y, z, rotY } | { kind:'held' } }

interface FurnitureState { id; type: 'shelf'|'storage_rack'|'fridge'|'freezer'; x; z; rotY /* кратно 90° */ }
```

Правила стока (инварианты, проверяются тестами):
- `0 ≤ reserved ≤ count ≤ capacity(8)`; `sku === null ⇔ count === 0` (пустая секция освобождает SKU).
- Покупатель резервирует → идёт → «берёт» (count−1, reserved−1) → в корзину. Отмена/уход → резерв снимается.
- Если покупатель бросает корзину — единицы возвращаются в исходные секции; не влезло — в коробку возврата в зоне доставки.
- Игрок не может забрать с полки зарезервированные единицы (ПКМ берёт только `count − reserved`).

## 4. Навигация

- **Граф дорог**: узлы по полилиниям дорог (данные карты), рёбра с длинами, A* по графу. Выходы: двери домов,
  прилавки, остановка, крыльцо магазина, края карты.
- **Сетка зала**: 0.25 м, статические стены/прилавок + динамическая мебель и коробки на полу (с отступом 0.25 м).
  A* (октильная эвристика, бинарная куча, типизированные массивы) → сглаживание по прямой видимости.
- Мебель ставится только если от входа достижимы все точки доступа к секциям и очередь.
- Расхождение агентов: мягкое расталкивание + ожидание, если впереди стоит другой агент.

## 5. Сохранение

`GameStateSnapshot` — JSON из `snapshot()` каждого сервиса + `version`. Без объектов three.js.
При загрузке: `restore()` сервисов → пересборка видов (мебель, товар, коробки, грязь, реставрация,
покупатели с перерасчётом пути из сохранённой позиции) → игрок и предмет в руках.

## 6. План оптимизации для браузера

| Приём | Где |
|---|---|
| Общие материалы (по имени), вершинные цвета вместо уникальных текстур | все модели |
| Слияние геометрии модели по материалу (1 меш на материал) | здания, пропсы |
| `InstancedMesh` | деревья, кусты, трава, цветы, камни, заборы, фонари, товар (по SKU) |
| Процедурные canvas-текстуры 256–1024, мипмапы, анизотропия ≤ 8 | доски, черепица, брусчатка, земля |
| Одна тень (солнце), камера тени следует за игроком, тени отбрасывают только здания/деревья/мебель | рендер |
| Точечные источники только в зале и 4–6 ближайших фонарей ночью; остальное — эмиссив | освещение |
| Туман + дальность прорисовки + frustum culling | улица |
| Пресеты Low/Medium/High: масштаб рендера, разрешение теней, плотность травы, пост-обработка | настройки |
| HUD обновляется ~10 Гц, DOM не перестраивается без изменений | UI |
| Пулы объектов для грязи, товара в полёте, пузырей | симуляция |
| Лимиты: ≤ 5 покупателей одновременно, ≤ 60 декалей грязи | симуляция |
| GLB без текстур, при необходимости Meshopt-сжатие (gltf-transform) | ассеты |

Бюджет (Medium, 1920×1080): ≤ 250 draw calls на улице, ≤ 150 в зале, ≤ 400k треугольников в кадре,
≤ 150 МБ JS heap, загрузка < 5 с на широком канале.
